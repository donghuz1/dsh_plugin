# 插件作者最小手册

一页纸。只讲写插件真正要用的概念；bundle、profile、seam、Cordis 术语等遇到具体问题再查。

## 一、只记三件事

1. **插件 = 一个包 + 一行配置。** 行写在 `cordis.patch.yml` 里，做 `insert`。
2. **代码 = 导出 `apply(ctx)`。** Host 半区的入口是 `index.js`，浏览器半区的入口是 `client.js` 里的 `__ModuleLoader__.load` 工厂。
3. **注册用 `ctx.effect` 包住。** 注册时拿到的 disposer 交给 effect 管理，插件停用即撤销。

其余概念都是这三条的推导：

- “替换内置实现” = 在 patch 里先 `disabled: true` 禁掉内置行，再 `insert` 自己的行；
- “依赖别的服务” = 导出 `inject`，或在代码里 `ctx.get('服务名')`；
- “往界面加东西” = `ctx.slots.register(...)`，同样包进 effect。

## 二、最小骨架

Host 半区，三个文件即可。

`package.json`：

```json
{
  "name": "@local/dsh-hello",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "exports": { ".": "./index.js" },
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

`cordis.patch.yml`：

```yaml
- insert:
    - id: hello
      name: '@local/dsh-hello'
```

`index.js`：

```js
/** 只用于 fiber 诊断；行 id 与包名由 package.json 决定。 */
export const name = 'hello'

export function apply(ctx) {
  // 真正的插件在这里注册能力，并要求撤销：
  //   ctx.effect(() => ctx.someService.register(...), 'hello: ...')
  //   ctx.effect(() => ctx.theme.overrideTokens(SOURCE, TOKENS), 'hello: tokens')
}
```

浏览器半区只多两处：`package.json` 加 `dsh.client`，`client.js` 用 `__ModuleLoader__.load({ id, factory })` 包一层；真实样例见 [qoder-theme/client.js](../../plugins/qoder-theme/client.js)。

装进 profile 用 `plugin_manager install_bundle <插件目录>`，步骤见 [根 README](../../README.md#安装一个新插件)；每次改完的验证命令见 [AGENTS.md](../../AGENTS.md) 第五节。

## 三、表 1：想改什么 → 用什么

| 想做的事 | 用什么 | 参考 |
| --- | --- | --- |
| 换参数 / 开关 | 按行 id 改 `config`（整段替换） | profile 的 patch |
| 换掉一个实现 | `disabled: true` + `insert` 自己的一行 | [session-title-rule/cordis.patch.yml](../../plugins/session-title-rule/cordis.patch.yml) |
| 加一个工具 / 命令 / provider | `ctx.<服务>.register(...)`，包进 `ctx.effect` | `plugins/session-title-rule/index.js:56` |
| 往界面加组件 | `ctx.slots.inject` + `ctx.slots.register` | [DSH 插件系统](../架构/dsh-插件系统.md) 第六节 |
| 改全站观感 | `ctx.theme.overrideTokens(source, tokens)` | `plugins/qoder-theme/client.js:337` |
| 硬依赖一个服务 | 导出 `inject = ['服务名']`；缺失时 `apply` 不执行 | `plugins/session-title-rule/index.js:27` |
| 可选依赖一个服务 | `ctx.get('服务名')`，缺失返回 `undefined` | `plugins/session-title-rule/index.js:210` |
| 拦截请求 / 工具调用 | `ctx.on('事件名', ...)` | `docs/参考/dsh-官方文档/event-producer-consumer.zh.md` |

## 四、表 2：没生效时按四层查

| 层 | 判据 | 常见原因 |
| --- | --- | --- |
| 1 装上了吗 | `plugin_manager` → `list_plugins` 里有没有你的行 | patch 路径不对、行没插进 profile |
| 2 加载了吗 | 该行 `fiberPhase` | `pending` = `inject` 的服务不存在；`failed` = `apply` 抛错或 Config 校验失败 |
| 3 注册进去了吗 | 按插件类型查 inspect：工具看 `tools`、服务看 `listService`、client 看 `/plugins/events` | 服务名 / slot 名 / 令牌名写错（字符串不校验，只静默失效） |
| 4 行为对吗 | 实际用一次 | 前两层都对，问题在使用侧或假设写错 |

## 五、两个真实插件对号入座

两个插件加起来只用了三条概念，其余都是写法差异。

### qoder-theme（浏览器半区）

| 代码位置 | 在做什么 | 概念 |
| --- | --- | --- |
| `plugins/qoder-theme/cordis.patch.yml:4` | 插一行 | ① 一行 |
| `plugins/qoder-theme/package.json` 的 `dsh.client` | 声明浏览器半区 | 包装字段，不是运行时概念 |
| `plugins/qoder-theme/index.js` | Host 半区空 `apply` | 占位：行需要能解析到入口 |
| `plugins/qoder-theme/client.js:332-334` | 导出 `name` / `inject` / `apply` | ② apply |
| `plugins/qoder-theme/client.js:337-338` | `overrideTokens` 交给 `ctx.effect` | ③ effect |

它的 Host 逻辑是空的，所以不需要读懂 Host 半区。

### session-title-rule（Host 半区）

| 代码位置 | 在做什么 | 概念 |
| --- | --- | --- |
| `plugins/session-title-rule/cordis.patch.yml:6-10` | 禁内置行 + 插自己的行 | ① 一行（替换写法） |
| `plugins/session-title-rule/index.js:27` | `inject` 硬依赖三个服务 | 依赖写法 |
| `plugins/session-title-rule/index.js:53` | `export function apply(ctx)` | ② apply |
| `plugins/session-title-rule/index.js:56-63` | 注册 provider 并纳入 effect | ③ effect |
| `plugins/session-title-rule/index.js:210` | `ctx.get('workspaceRegistry')` | 可选依赖写法 |

它的浏览器半区 `client.js` 是空壳，只有包清单需要它。

### 结论

两个插件都没有用到 bundle 编排、profile 组合、seam 设计、声明合并；它们只是把“一行 + apply + effect”各写了 1-2 个变体。遇到别的插件看不懂时，先找它的这三样，其余都是细节。

## 七、刻意不学（等遇到再学）

- **bundle / profile 的编排**：只在你需要分发“一套组合”时才有用；单个插件会写 `cordis.patch.yml` 就够了。
- **服务定义（seam）**：只有你要给别的插件提供新能力、且需要可替换实现时才设计。
- **事件五种分发模式**：先只用 `ctx.on`；写拦截器时再确认它是 `waterfall` 还是 `serial`。
- **声明合并**：树外插件用纯 JS 也能跑；要类型安全时再补。

# 上手路线：从会 TS 到能写 DSH 插件

给已有 TypeScript 基础、但还没摸过 DSH 架构的人。回答两个问题：**需要补哪些前置知识**、**能做什么**。

只想用最少概念写第一个插件：先看 [插件作者最小手册](插件作者最小手册.md)，再按本文补前置知识。

## 一、先破除三个误解

1. **不需要懂 Electron。** 插件不跑在渲染进程。Host 半区跑在 `apps/desktop-host` 那个 Node 子进程里，浏览器半区跑在页面上。整个 Electron 壳（窗口、协议、cookie、更新）与插件作者无关。
2. **不需要构建工具链。** 零构建可行：`client.js` 手写，`index.js` 手写，不装任何依赖。本项目 `plugins/qoder-theme` 唯一的构建脚本是为了把 CSS 当一等公民，不是 DSH 的要求。
3. **不需要读遍源码。** 但有 7 篇教程必须读，读完能省掉大部分试错。

## 二、真正的前置知识

以下四条不学就寸步难行。全部有中文文档，按顺序读。

### 1. Cordis 插件模型（地基）

本地快照的 [Cordis 七章教程](../参考/dsh-官方文档/cordis-tutorial/index.zh.md)，从零讲清插件是什么、`ctx` 是什么、服务与事件怎么用、配置怎么校验、组合与 HMR 怎么工作。

必读，别跳过。DSH 的每一处设计都建立在这个模型上。

### 2. 依赖注入的 `PENDING` 语义

`inject: ['tools']` 是**硬依赖**：服务不存在时 fiber 停在 `PENDING`，**不执行 `apply`，也不抛错**；服务出现后自动加载，消失后自动卸载。

不理解这条，你会花大量时间困惑"为什么我的 `apply` 没跑"。对照读 [03-services](../参考/dsh-官方文档/cordis-tutorial/03-services.zh.md)。

可选依赖走 `ctx.get(name)`，**不要**用 `ctx.name`——属性代理沿祖先链解析，未声明的读会抛错。

### 3. effect 的撤销模型

任何不是通过 Cordis API 建立的资源，都必须包在 `ctx.effect()` 里，否则插件停用后会留残留。

`ctx.on` / `ctx.provide` / `ctx.plugin` 本身已经是 effect；`ctx.set` **不是**。

对照读 [02-lifecycle-and-effects](../参考/dsh-官方文档/cordis-tutorial/02-lifecycle-and-effects.zh.md)。

### 4. profile / bundle / 行 三层

回答"我的插件是怎么进到应用里的"：

- **profile** 是一个具名组合（`desktop` / `web`）；
- **bundle** 是一个 patch 层，向 profile 插行；
- **行** 才是真正被加载的插件。

详见 [DSH 插件系统](../架构/dsh-插件系统.md) 前三节。

## 四、TS 侧需要补的

只有一个：**`declare module` 类型合并**。

DSH 大量用它给 `ctx` 和事件加类型，例如：

```ts
declare module '@deepseek-ai/cordis' {
  interface Context {
    tools: ToolRuntime
  }
  interface Events {
    /**
     * Allow, deny, cancel, or ask before dispatch.
     * @mode waterfall
     */
    'tools/pre-execute'(this: Scoped<ToolRuntime>, exec: ToolExecution, next: () => Promise<PreToolDecision>): Promise<PreToolDecision>
  }
}
```

它不生成任何运行时代码——没有这段声明，服务在运行时照常工作，只是消费方失去类型安全。

其余泛型、条件类型会读到就够，不需要精通。

## 五、你能做啥：能力地图

按投入产出排序。每级都给出真实的参考实现，读代码比读文档快。

### 第 1 级 · 零代码或近乎零代码

| 能做 | 需要的前置 | 参考 |
| --- | --- | --- |
| **纯配置 bundle**：插一个现成的插件并配好它（如接一个 MCP server），自己一行代码不写 | 会写 YAML | `cordis-plugin-development` skill 里的 MCP 例子 |
| **主题皮肤**：覆盖设计令牌改变整个界面观感 | 会 CSS + 一个 JS 文件 | 本仓库 `plugins/qoder-theme` |
| **静态界面装饰**：往 slot 里插一个只读组件（徽标、提示条） | 会一点 React | `cordis-plugin-development` skill 里的 slot 例子 |

这一级的共同点：**没有 Host 状态**，是数据 + 声明。一两小时能出成果，适合建立信心。

### 第 2 级 · 监听事件，无自有服务

| 能做 | 需要的前置 | 参考 |
| --- | --- | --- |
| **工具插件**：给 agent 加一个新能力（最典型的插件） | inject + `ctx.tools.register()` | `packages/fs/tool-fs`、`packages/web/tool-web` |
| **钩子插件**：拦截工具调用做权限门禁、审计、改写 | waterfall 的 `next()` 否决语义 | `packages/hooks/hooks-codex` |
| **生命周期钩子**：`agent/created` / `agent/pre-step` / `turn/end` | serial / emit 模式 | [事件生产/消费矩阵](../参考/dsh-官方文档/event-producer-consumer.zh.md) |
| **界面上加功能**：往 list slot 加按钮或一行 | Slot + React | `packages/client/ui-*` |

这一级是绝大多数实用插件的所在。**建议把这里当主战场。**

### 第 3 级 · 提供自己的服务与契约

| 能做 | 需要的前置 | 参考 |
| --- | --- | --- |
| **服务插件**：`Service` 子类，供别的插件 inject | DI 拓扑 + 类型合并 | `packages/core/tools`（`ToolRuntime`）、`packages/storage/storage-json` |
| **LLM adapter**：接一个新的模型提供方 | Provider 契约 | `packages/llm/llm-deepseek` |
| **Remote API**：把 Host 能力暴露给浏览器半区 | Typert / Remote 生成链 | `packages/api/*`、[adding-a-remote-api](../参考/dsh-官方文档/cookbook/adding-a-remote-api.zh.md) |

### 第 4 级 · 改交互骨架

| 能做 | 需要的前置 |
| --- | --- |
| 自定义聊天节点渲染器（`conversation.chat.node` 键控 slot） | 会话事件流 + slot 的 keyed/chain 语义 |
| 替换既有 UI（shadowing） | slot 遮蔽规则、替换风险 |
| 自定义 subagent provider / workflow 引擎 | per-agent 作用域、单调守卫 |

这一级要动别人也依赖的东西，建议先用前三级把 DSH 的模型吃透。

## 六、建议的第一个练习

**做一个纯 Host 的工具插件**，插一个 `hello` 工具，接收一个名字参数并返回问候。

理由：

- 它逼你走完最小完整链路（package.json / patch / Host 入口 / 装进 profile / 看激活警告），但不涉及浏览器半区与 React；
- 它让你第一次直面 `inject` 的 `PENDING` 语义（工具注册通常依赖 `ctx.tools`）；
- 验证方式明确：装好后在会话里让模型调用它。

跑通后再按兴趣分流：想做视觉就走 `plugins/qoder-theme` 那条路；想做能力就继续做工具与钩子。

## 七、学习顺序（时间盒）

| 阶段 | 做什么 | 产出 |
| --- | --- | --- |
| 0（半天） | 读 [Cordis 七章教程](../参考/dsh-官方文档/cordis-tutorial/index.zh.md) | 知道 `ctx` / 服务 / effect / 事件是什么 |
| 1（1 小时） | 读 [DSH 插件系统](../架构/dsh-插件系统.md) | 知道插件怎么进 profile、四个身份字符串、静默失败清单 |
| 2（1 天） | 抄最小骨架装进 profile，确认链路通 | 一个"装了但什么都不做"的插件 |
| 3（按兴趣） | 选第 1 或第 2 级的题目做 | 第一个真实插件 |

阶段 2 别省。DSH 的错误大多是静默的，**先把"装上了"和"没生效"分清楚**，后面会省掉大量困惑。

## 八、心态上的一条

DSH 里绝大多数失败没有报错。养成两个习惯：

1. **查而不是猜**：`cordis_inspect_list` → `cordis_inspect_query`，读 Service / Event / Config / Slots / Theme 的确切契约。别照抄别人的实现去猜 API 长什么样。
2. **给字符串假设写测试**：令牌名、slot 名、事件名写错都只静默失效。[DSH 插件系统](../架构/dsh-插件系统.md) 第十二节有完整的「症状 → 原因」对照表。

# 主题覆盖走令牌层

- 状态：实施
- 日期：2026-09-27
- 编号：0001
- 关联 commit：`feat: Qoder 主题插件——令牌层覆盖与契约门禁`

## 背景

为 DSH 桌面端做 Qoder 风格皮肤。初版方案是插件在 `apply` 里把一份 CSS 字符串塞进 `<style>` 标签，靠 `html body[data-ds-dark-theme]` 的特异性压过 `ui-theme` 的样式表。

在查客户端 Service 目录时发现 `ctx.theme.overrideTokens(source, tokens)`：DSH 已有的第三方主题接口，按来源分层、运行时校验、返回 disposer。

## 决策

覆盖改走 `ctx.theme.overrideTokens`，不再注入样式表。

- 每个令牌以 `{ light, dark }` 成对给出，由 `src/*.css` 声明，`build.mjs` 编译成令牌表并断言亮/暗两侧令牌集合逐个对应。
- 覆盖对象是 `--dsw-static-*` 色阶，不是 165 个 `--dsw-alias-*` 别名。DSH 的静态色阶在亮/暗块中共用、语义由别名映射决定，改色阶即可让全部别名自动重算。
- 被多个角色共用的色阶步骤（如 `bluish-900` 同时承担侧栏底色与代码块底色）在 `alias.*.css` 里单独拆开。

## 理由

1. 落地方式是 `body` 上的内联自定义属性，天然压过任何选择器，因此没有特异性之争，也不依赖样式表加载顺序。
2. 亮/暗由 API 的形状强制要求，不再需要手写 `body[data-ds-dark-theme]` 选择器。
3. disposer 与 `ctx.effect` 对齐，停用插件即精确撤层——「停用后恢复原生观感」由构造保证，而非靠人工清理。
4. 是 DSH 承认的扩展点，不会随内部样式表重构而失效。

初版方案的三条代价随之消失：特异性要算准、加载顺序不能反、样式表要么硬删要么留残留。

## 替代方案

- **注入 `<style>` 样式表**（初版）。能表达令牌表达不了的东西（伪元素、几何、`[data-slot]` 结构选择器），但把主题变成对内部选择器的依赖，且要自行处理清理与顺序。
- **`ctx.theme.register(ThemeDefinition)` 注册完整主题**。语义上更贴切，但会占用一个主题 id 并要求用户切换主题偏好才看得到；本插件的意图是叠加在既有亮/暗之上，`overrideTokens` 的分层语义更合适。
- **改 DSH 源码里的 `design-platform.css`**。直接改上游、随版本升级即丢，且不属于「插件」。

## 影响

- 令牌名拼错不会被 API 拦下（`overrideTokens` 只校验值形状），只会静默不生效。`test/contract.test.mjs` 把 79 个令牌名对照 DSH 真实样式表逐个校验来兜住这个风险；已实测注入一个错误令牌名可让该用例失败。
- 令牌表达不了的东西即无法覆盖。圆角是主要缺口：DSH 没有圆角语义令牌，`border-radius` 是 176 个 CSS module 里的字面量。
- `client.js` 成为生成物，`src/*.css` 是唯一真源。
- 该接口不接受裸字符串值，亮/暗必须成对；`build.mjs` 的对称断言把这个约束前移到构建期。

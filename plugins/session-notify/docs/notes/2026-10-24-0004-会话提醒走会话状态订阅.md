# 会话提醒走会话状态订阅

状态：implemented
类别：feature
日期：2026-10-24
插件：session-notify

## 背景

DSH 的审批请求只接管当前会话的 composer，会话完成只更新侧栏/工作区状态；用户离开窗口后没有任何系统级提醒。需求是在「需要审批」和「会话完成」时各弹一条桌面系统通知，并在点击后回到对应会话。

可用的客户端信号有两个：`remote.$on('approval/request')`（Remote Event waterfall）与 `ctx.uiSession.sessionStatus`（运行状态 + pending interaction 的会话状态投影）。

## 决策

- 浏览器半区订阅 `ctx.uiSession.sessionStatus`：
  - `pendingInteraction.kind === 'approval'` 时按 `pending.key` 去重提醒；
  - 对每个会话记录上一轮 `running`，`true → false` 时提醒一次；
  - 完成提醒只覆盖根会话（跳过 `origin === 'subagent'` / 有 `parentSessionId` 的子会话）；
  - 当前正在看且页面可见/聚焦的会话不弹完成提醒；
  - 点击通知执行 `window.focus()` 与 `ctx.get('uiWorkspace')?.openSession(sessionId)`。
- 通知用渲染层 `new Notification(...)`；不新增 Host 半区行为。

## 理由

- `approval/request` 是 waterfall，`ui-approval` 的监听器会接管并等待用户作答（不调用 `next()`），后注册的观察者永远收不到；`sessionStatus` 正是它发布 pending 之后的投影，覆盖所有会话（侧栏的「等待审批」也来自这里）。
- 插件不能往 Electron 主进程加代码；渲染层 `Notification` 在 Desktop 走 Electron 的系统通知，浏览器访问时退化为浏览器通知，零依赖。
- Desktop 主进程的 `setPermissionRequestHandler` 对非 media 权限直接放行，`dsh-app://` 又注册为 secure context，因此桌面端不需要额外授权流程。
- `completionUnread` 只在非主视图会话上置位，且打开会话即清除，不能表达「用户离开时当前会话完成」；直接比较 `running` 才能覆盖该场景。

## 替代方案

| 方案 | 放弃原因 |
| --- | --- |
| 监听 `remote.$on('approval/request')` | 被 `ui-approval` 的 waterfall 监听器接管，后注册者收不到事件。 |
| 监听 Host `session/event` 再由主进程发系统通知 | 插件无法向 Electron 主进程注入代码；需要自建 Host→Renderer 桥与平台分支，超出「最小客户端插件」范围。 |
| 在聊天记录里插入系统消息行 | 不是系统通知；用户要求的是离开窗口也能看到的提醒。 |
| 只用 `completionUnread` 判定完成 | 只覆盖非主视图会话，且打开会话即清除；漏掉「当前会话在窗口失焦时完成」。 |
| 轮询会话状态 | `sessionStatus` 已是可订阅快照，轮询只会重复造机制。 |

## 影响

- 完成提醒按「一轮结束」触发，失败/中止也会提醒，文案不区分结果。
- 应用完全退出后没有通知；页面隐藏但存活时仍会弹。
- 浏览器端首次通知需要授权；拒绝后只剩侧栏状态。
- 契约测试对照源码检出（0.1.7-rc.2），运行时实测为 0.2.1-rc.3；源码中缺失的路径会显式跳过并在输出里说明。
